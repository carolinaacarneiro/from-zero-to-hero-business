FUNDAMENTOS · 1 DE 7

Lakehouse y Delta Lake

Dónde viven los datos

Qué es

Un lakehouse guarda los datos en el almacenamiento barato de la nube (el data lake) pero con las garantías de un data warehouse: transacciones, esquemas y rendimiento. El formato que lo hace posible es Delta Lake: archivos Parquet abiertos + un registro de transacciones.

Por qué importa
  • Una sola copia de los datos para todos los usos: no hay que copiar entre sistemas
  • Transacciones ACID: nadie lee una tabla a medio escribir
  • Time travel: consultar cómo estaba la tabla en una versión anterior
  • Formato abierto: tus datos no quedan atados a un proveedor
Cómo funciona
1Archivos en la nube (S3, ADLS, GCS)
2Delta Lake: Parquet + registro de cambios
3Tablas en Unity Catalog
4SQL, BI, ML e IA sobre la misma copia
En el lab
-- Historial de cambios de una tabla Delta
DESCRIBE HISTORY fromzerotohero.churn.dim_cliente;

-- Time travel: la tabla en su primera versión
SELECT * FROM fromzerotohero.churn.dim_cliente VERSION AS OF 0;
Analogía
Un depósito enorme y barato (el lago) con el orden y el inventario de un supermercado (el warehouse).
No entrar en detalles de Parquet. Mensaje: todas las herramientas del día leen la MISMA copia de los datos.

SQL Editor + Genie Code

Preguntar a los datos, con un copiloto

Qué es

El SQL Editor es donde escribes consultas y ves el resultado en tabla o gráfico. Genie Code vive dentro del editor: lee los metadatos de Unity Catalog (tablas, columnas, comentarios y relaciones) para escribir SQL que encaja con tus datos.

Por qué importa
  • No necesitas memorizar la sintaxis: empiezas a aportar desde el minuto uno
  • /explain explica una consulta ajena; /fix o Diagnose error corrige errores
  • Los comentarios de las tablas mejoran las respuestas: documentar es invertir en IA
  • Usa el SQL Warehouse y tus permisos: no ve datos que tú no puedas ver
Cómo funciona
1Describes en español lo que quieres
2Genie Code lee el catálogo: tablas y comentarios
3Propone el SQL (y lo explica)
4Tú revisas, ejecutas y aceptas
En el lab
SELECT p.nombre_plan,
       ROUND(AVG(s.churn_flag) * 100, 1) AS tasa_churn_pct
FROM fromzerotohero.churn.hecho_suscripcion s
JOIN fromzerotohero.churn.dim_plan p ON s.id_plan = p.id_plan
GROUP BY p.nombre_plan
ORDER BY tasa_churn_pct DESC;

MÓDULO 02 · CÓMO FUNCIONA

SQL Alerts

Una consulta que vigila por ti

Qué es

Una alerta ejecuta una consulta según una programación, compara un valor con una condición y notifica cuando se cumple. No necesitas abrir un reporte para enterarte de que algo cambió.

Por qué importa
  • Monitoreo proactivo: el dato te busca a ti, no al revés
  • Estados claros: OK, Triggered (se cumplió) o Error (la consulta falló)
  • Corre en el SQL Warehouse con los permisos de Unity Catalog
  • Los destinos (Slack, Teams, webhook) los configura un administrador una sola vez
Cómo funciona
1Consulta (tasa de churn %)
2Programación: ej. todos los días 08:00
3Condición: tasa_churn_pct > 25
4Notificación: e-mail, Slack, Teams o webhook
En el lab
-- Alerta principal: condición  tasa_churn_pct > 25
SELECT ROUND(AVG(churn_flag) * 100, 1) AS tasa_churn_pct
FROM fromzerotohero.churn.hecho_suscripcion;

-- Variación: condición  nps_promedio < 7
SELECT ROUND(AVG(nps), 2) AS nps_promedio
FROM fromzerotohero.churn.hecho_ticket_soporte;
Analogía
Un detector de humo: no lo miras todo el día, pero suena cuando importa.

MÓDULO 03 · CÓMO FUNCIONA

Metric Views

La capa semántica dentro de Unity Catalog

Qué es

Una metric view define en YAML, una sola vez, la tabla fuente, los joins, las dimensiones (cómo cortar: Segmento, Plan, Mes) y las medidas (qué calcular). Después cualquiera pide la métrica por su nombre con MEASURE(), sin repetir la fórmula.

Por qué importa
  • Una fórmula oficial: se acaba el “¿por qué tu número no coincide con el mío?”
  • Las tasas se calculan bien en cualquier nivel de agregación (una tasa no se suma)
  • Gobernada como una tabla: permisos, comentarios y linaje
  • La reutilizan los Dashboards (Ej. 5) y los Genie Agents
Cómo funciona
1source: la tabla de hechos
2joins: cliente y plan
3dimensions + measures
4MEASURE() en SQL, dashboards y Genie
En el lab
CREATE VIEW mvw_churn WITH METRICS LANGUAGE YAML AS $$
version: 0.1
source: fromzerotohero.churn.hecho_suscripcion
joins: [{name: cliente, source: fromzerotohero.churn.dim_cliente,
         'on': source.id_cliente = cliente.id_cliente}]
dimensions: [{name: Segmento, expr: cliente.segmento}]
measures:   [{name: Cancelaciones, expr: SUM(source.churn_flag)}]
$$;

SELECT Segmento, MEASURE(Cancelaciones) FROM mvw_churn GROUP BY ALL;
Analogía
La receta oficial de la casa: todos los cocineros preparan el plato igual.
NO mostrar todavía la medida Tasa de Churn: el error plantado (COUNT) se descubre en el Ej. 5.

MÓDULO 04 · CÓMO FUNCIONA · 1 DE 2

AI Functions

IA generativa como si fuera una función de SQL

Qué es

Funciones de SQL que llaman a un modelo de lenguaje por cada fila. Se usan como cualquier otra función: SELECT ai_analyze_sentiment(texto) FROM tickets. Databricks se encarga de enviar las filas en lotes a los modelos fundacionales que ya están desplegados en la plataforma.

Por qué importa
  • ai_analyze_sentiment: positive, negative, neutral o mixed
  • ai_classify: elige una etiqueta de tu lista · ai_summarize: resume el texto
  • ai_mask: oculta nombres, teléfonos y e-mails (PII) antes de compartir
  • Sin Python ni APIs; los datos no salen de la plataforma. Costo por token: usa LIMIT al probar
Cómo funciona
1Tu consulta SQL
2Databricks agrupa las filas en lotes
3Modelo fundacional (Foundation Model APIs)
4Resultado como una columna nueva
En el lab
SELECT id_ticket,
       ai_analyze_sentiment(texto_reclamo)                AS sentimiento,
       ai_mask(texto_reclamo, ARRAY('person','phone','email')) AS texto_anonimo
FROM fromzerotohero.churn.hecho_ticket_soporte
LIMIT 20;
Analogía
Un analista que lee miles de tickets en segundos y anota al margen lo que siente el cliente.
La IA no es 100% determinista: puede variar en casos límite. Lo que importa es la tendencia.
MÓDULO 04 · CÓMO FUNCIONA · 2 DE 2

ai_query y los modelos fundacionales

Tú eliges el modelo y escribes el prompt

Qué es

ai_query(modelo, prompt) es la función general: le pasas el nombre de un endpoint (ej. Llama o GPT OSS, ya desplegados por Databricks y cobrados por token) y un prompt armado con las columnas. Cambiar de modelo es cambiar un nombre.

Por qué importa
  • Control total de las instrucciones y del formato de salida
  • Comparar modelos (calidad, velocidad, costo) con la misma consulta
  • Buen prompt: pide una sola palabra, da la lista de opciones, define el formato
  • Los modelos se ven en Serving y se gobiernan con Unity Catalog
Cómo funciona
1Elegir el endpoint del modelo
2Armar el prompt con CONCAT(...)
3Ejecutar sobre las filas
4Validar el resultado
En el lab
SELECT texto_reclamo,
       ai_query('databricks-meta-llama-3-3-70b-instruct',
         CONCAT('Clasifica el sentimiento en UNA palabra ',
                '(positivo, negativo o neutral): ', texto_reclamo)) AS sentimiento
FROM fromzerotohero.churn.hecho_ticket_soporte
LIMIT 10;
Analogía
Las AI Functions son platos del menú; ai_query es pedirle al chef exactamente lo que quieres.
Mostrar Serving → Foundation models para que vean de dónde salen los nombres de los endpoints.

MÓDULO 06 · CÓMO FUNCIONA · 1 DE 2

Cómo aprende un modelo de churn

Machine Learning sin misterio

Qué es

Un modelo aprende patrones del pasado (quién canceló y quién no) para estimar la probabilidad de cancelar de cada cliente hoy. Usamos Gradient Boosting: muchos árboles de decisión pequeños que se corrigen entre sí.

Por qué importa
  • AUC: 0,5 = moneda al aire · 1,0 = perfecto. Hoy ≈ 0,97 (datos sintéticos)
  • nivel_riesgo: Alto ≥ 0,50 · Medio ≥ 0,25 · Bajo
  • factor_principal: la señal que más pesa en ese cliente, para poder actuar
  • En datos reales un AUC de 0,75–0,85 ya es muy útil
Cómo funciona
1Historia: feature_churn (uso, CSAT, NPS, atrasos…)
275% para entrenar · 25% para el examen
3Entrenar el Gradient Boosting
4Medir el AUC con datos que no vio
5prob_churn de cada cliente
En el lab
Xtr, Xte, ytr, yte = train_test_split(X, y, test_size=0.25, stratify=y)
pipe = Pipeline([("pre", pre), ("clf", GradientBoostingClassifier())])
pipe.fit(Xtr, ytr)
auc = roc_auc_score(yte, pipe.predict_proba(Xte)[:, 1])
Analogía
Estudiar con unos ejercicios y rendir el examen con otros: así sabes si aprendiste o memorizaste.

MLflow registra cada entrenamiento (un run): parámetros, métricas como el AUC y el modelo. Al registrarlo en Unity Catalog queda como fromzerotohero.<tu_schema>.modelo_churn: con dueño, versiones, permisos y linaje, igual que una tabla.

Por qué importa
  • Reproducible: sabes con qué datos y métricas se creó cada versión
  • Versiones: comparar y volver atrás sin perder nada
  • Permisos: quién puede usar o actualizar el modelo
  • Linaje: de feature_churn al score que ve el equipo de retención
Cómo funciona
1Run de MLflow (AUC)
2Modelo registrado en UC (v1, v2…)
3Scoring de todos los clientes
4Tabla churn_scores
5Dashboard, Genie y la app la consumen
En el lab
mlflow.set_registry_uri("databricks-uc")
with mlflow.start_run(run_name="modelo_churn"):
    mlflow.log_metric("auc", auc)
    mlflow.pyfunc.log_model(name="model", python_model=ChurnProb(pipe),
        registered_model_name=MODEL)

El historial clínico del modelo: qué se le hizo, cuándo, con qué resultado y quién lo firmó.

Genie Agents

Especialistas que responden preguntas de negocio

Qué es

Un Genie Agent es un espacio de preguntas y respuestas sobre las tablas que tú eliges. Traduce la pregunta a SQL, la ejecuta en el warehouse con tus permisos y responde con texto, tabla, gráfico y el SQL usado.

Por qué importa
  • Instructions: reglas del negocio (ej. el año fiscal empieza en octubre)
  • SQL de ejemplo para las preguntas frecuentes: la forma “oficial” de calcular
  • Un especialista por dominio: menos tablas = respuestas más precisas
  • Transparente: siempre puedes ver y auditar el SQL
Cómo funciona
1Pregunta en español
2Contexto: tablas, comentarios, instrucciones y SQL de ejemplo
3SQL generado y ejecutado
4Respuesta + SQL visible
En el lab
Pregunta:  ¿Cuál es el NPS promedio del año fiscal 2024 en Costa Rica?
Sin regla: asume año calendario            → 7,3
Con la regla del año fiscal (Instructions)  → 6,5
Analogía
Un analista nuevo: sabe SQL, pero necesita que le cuentes las reglas de la casa.

Genie One

Una sola puerta de entrada para el negocio

Qué es

Genie One es la experiencia de Databricks para usuarios de negocio: una pantalla para encontrar dashboards, Genie Agents y apps, y preguntar en lenguaje natural. Busca entre todas las fuentes a las que tienes acceso y cita de dónde salió cada respuesta.

Por qué importa
  • Con @ eliges al especialista exacto: el camino más confiable
  • Sin @, puede elegir la fuente de otra persona si tienes acceso a ella
  • Por eso la regla de oro: mira siempre la cita
  • Patrón multi-agente: varios especialistas + una puerta de entrada
Cómo funciona
1Pregunta (o @Soporte - tu_schema)
2Elige la fuente entre las que puedes ver
3Responde y cita la fuente
4Tú verificas la cita

UC Functions

Reglas de negocio gobernadas y reutilizables

Qué es

Funciones SQL guardadas en Unity Catalog (catálogo.schema.función). Encapsulan una regla de negocio para que personas, dashboards, agentes y apps la apliquen exactamente igual.

Por qué importa
  • La regla decide, la IA redacta: nunca inventa un descuento
  • Permisos con GRANT EXECUTE: quién puede usar cada regla
  • Una sola versión de la regla: la app del Ej. 9 llama a la misma función
  • Las funciones también sirven como herramientas para agentes de IA
Cómo funciona
1get_cliente_360(id): cliente + plan + score
2CASE WHEN decide las 3 ofertas
3generar_email_retencion(id)
4ai_query solo redacta el texto
En el lab
CASE WHEN DATEDIFF(DATE '2026-09-23', c.fecha_registro) >= 5 * 365
     THEN '15%' ELSE '10%' END                     AS descuento,
CASE WHEN s.nombre_plan = 'Básico' THEN '10 GB de internet gratis'
     ELSE 'el doble de tu internet actual + WhatsApp' END AS oferta_internet

SELECT * FROM get_cliente_360('C01575');
Analogía
El reglamento de la empresa: el vendedor (la IA) habla bonito, pero las condiciones están escritas.
Mensaje de confianza para el negocio: la IA nunca queda a cargo de una decisión comercial.

Databricks Apps

Aplicaciones web dentro de la plataforma

Qué es

Databricks Apps aloja aplicaciones web (Node.js/React o Python) dentro del workspace: sin servidores que administrar, con el login de Databricks y acceso directo a warehouses, Genie Agents y modelos.

Por qué importa
  • On-behalf-of (OBO): cada persona ve solo lo que Unity Catalog le permite
  • Scopes (sql, genie, ai-gateway…): limitan qué puede hacer la app en tu nombre
  • Sin infraestructura: Databricks hospeda, escala y protege la URL
  • Todo queda auditado como si lo hubieras hecho tú
Cómo funciona
1Código: app.yaml + Node.js/React
2Deploy: instala dependencias y arranca
3El usuario abre la URL y hace Authorize
4La app actúa con su identidad (on-behalf-of)

Unity Gateway

La puerta gobernada hacia los modelos de IA

Qué es

En vez de llamar a un modelo directamente, la app llama a un model service de Unity Gateway (fromzerotohero.<tu_schema>.retencion-gateway). El gateway aplica reglas y registra cada llamada.

Por qué importa
  • Control de costos: límites de uso por servicio
  • Auditoría: qué se preguntó y qué respondió el modelo, en una tabla Delta
  • Cambiar de modelo sin tocar el código de la app
  • Permisos de Unity Catalog sobre quién puede usar el servicio
Cómo funciona
1La app llama al model service
2Valida permisos y límite: 60 por minuto
3Enruta al modelo (gpt-oss-20b)
4Registra en la tabla de inferencia
